# 这个目录是什么

2026-09-14 那一轮改动的一次代码 review，以及它自带的复现用例。九个问题**全部已修**
（提交 `10b8fcf`）。

## 复现用例现在是红的，这是对的

`*.probe.test.ts` 断言的是**修复之前**的缺陷行为，所以：

- **红 = 那个 bug 已经修好了**
- 绿 = 还在复现

跑：

```sh
npx vitest run --config design/reviews/2026-09-14-changes/vitest.config.ts
```

当前五条里四条是红的。唯一还绿着的是「临时空页阻止后续重试」——它断言「连续两次
立刻调用只打一次 SDK」，而这个抑制本身是对的，不该每滚一下就把刚返回空的游标再问
一遍。修的是它不再**永久**封死（加了冷却，同步完成时一并解开），所以那条现在描述的
是防抖，不是缺陷。

## 正式的回归测试在哪

这些 probe 不进 `npm test`（主配置只收 `src/**/*.test.ts`）。对应的正式回归测试是：

- `src/renderer/src/store/session.paging.test.ts` —— 历史分页与大群成员，五条
- `src/renderer/src/views/markdown.test.ts` 的「单元格里的竖线」—— 四条

留着这个目录是为了记录当时发现了什么、怎么复现的。要改这些代码之前，先读一遍 review.md
里对应那一节，比重新推导快。
