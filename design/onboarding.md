# 新用户 onboarding 方案

内部使用，唯一的门是邀请码。目标：一个从没见过这个 app 的同事，拿到一段邀请文案，
两分钟内进来、知道这里有什么、和一个 agent 说上第一句话；邀请的人知道 TA 到了。

## 全流程

```
邀请方（设置 → 成员与邀请）                     新同事（首次打开 app）
──────────────────────────                    ─────────────────────────────────────────
生成邀请码 ──► 复制邀请文案 ──► 贴给对方 ──►   ① 邀请码   剪贴板里有码就预填；服务端先验
（下载地址 + 码 + 有效期）                       │          抄错 / 用过 / 过期当场说清
                                                ▼
                                              ② 你是谁   昵称 + 实时头像预览；显示「X 邀请你加入」
                                                │          名字撞了留在这步，码出问题退回 ①
                                                ▼
HALX 私信：「X 用你的邀请码进来了」 ◄──────   ③ 进来     壳出来，主区是欢迎页（Welcome）
把 TA 拉进频道 / 打招呼                          │          三件事 · 从一个 agent 开始 · 把人拉进来
                                                ▼
                                              agent 会话空态：自我介绍 + 三句开场；侧栏空组带动作
```

## 各步细节

### ① 邀请码（`views/SignIn.tsx`）
- 输入边打边整理：大写、自动加连字符、最长 `YPTD-XXXX-XXXX`；粘贴整段文案也能从中抓出码。
- 打开卡片时读一次剪贴板（主进程 `clipboard.readText`，不弹权限），命中就预填并提示「已从剪贴板填入」。
- 「下一步」先问服务端 `POST /v1/invites/check {code}`（未登录可用，码走 body 不进访问日志）：
  `invalid` 格式不对 / `unknown` 没这个码 / `used` 用过了 / `expired` 过期了，各有一句人话；
  通过则拿到 `expires_at` 和 `invited_by`（发码人的昵称）。
- 连不上服务器：显示原因，码留在框里。

### ② 你是谁
- kicker 显示「{邀请人} 邀请你加入」（命令行生成的码没有邀请人，退化为「第 2 步 / 共 3 步」）。
- 昵称输入右侧是实时的头像预览（首字 + 按名字取色），让人看到自己在别人那里长什么样。
- 提示：昵称随时能改，账号名按昵称生成之后不能改；底部提示码还有约几小时有效。
- 「创建账号并登录」：登录过程的状态显示在同一行；`user_exists` 留在本步给出提示，
  码相关的错误（被人抢先用了、刚过期）退回 ①，错误原样带回去。

### ③ 进来（`views/Welcome.tsx`）
注册成功 → `ui.welcome = true`（持久化）。主区没选会话时显示欢迎页而不是普通空态：
- 「你好，{昵称}」+ 三张卡：频道里 @agent 就是派活（先 👌 再回答）；和 agent 单聊看得见思考；⌘K 找一切。
- 「从一个 agent 开始」：名册里每个 agent 一张卡，带服务端的自我介绍和 tag，「开始对话」打开私聊并把
  第一句话放进输入框（"你好！先介绍一下你能帮我做什么，怎么问你效果最好？"）。
- 底部：频道要有人拉——「新建频道」「邀请同事」「先逛逛」。
- 收起条件：打开任何会话、点「先逛逛」。设置 → 关于与更新 里「再看一遍新手引导」。

### 之后的第一眼
- agent 私聊空态（`views/Stream.tsx`）：标题「和 X 的对话从这里开始」，正文是它的自我介绍，
  下面三颗开场药丸（你能帮我做什么？/ 用三句话介绍你自己 / 帮我看看这个：），点一下进输入框。
- 侧栏空组（`shell/ContextSidebar.tsx`）：「还没有频道 · 新建一个」「还没有私聊 · ⌘K 找人」。

### 邀请方（`views/Settings.tsx` 成员与邀请）
- 生成码之后多一个「复制邀请文案」：一段能直接贴给对方的话——两个架构的安装包稳定地址
  （`/dl/desktop/yptd-latest-{arm64,x64}.dmg`，`publish.sh` 每次发版把链接指到新版）、码、有效期。
- 对方注册成功后，服务端以第一个 agent（HALX）的身份私信邀请人：「X（@id）用你的邀请码进来了，
  去打个招呼或把 TA 拉进频道吧」——新账号的侧栏是空的，得靠邀请人拉进频道。
  邀请码记录了 `created_by`（命令行生成的码没有，不通知）。

## 服务端改动（yptd-serve）
- `POST /v1/invites/check`：未登录可用，回 `{valid, reason, expires_at, invited_by}`。
- 邀请码带 `created_by`；`RedeemInvite` 回整条记录；注册成功后 `welcomeInviter` 异步私信。

## 有意没做（要做时再说）
- **默认频道自动加入**：注册时把新人拉进一个「大厅」。服务器上现在有多个真实群、没有唯一的主群，
  加人进群是对外动作，等定了哪个群再加一个 `YPTD_HOME_GROUPS` 配置即可（注册 → 邀请入群）。
- `yptd://invite/<code>` 深链：点邀请链接直接带码打开 app。要注册 URL scheme 和打包配置。
- 注册时上传头像：上传要先登录 IM，放在欢迎页或资料页更顺；现在资料页已能换。
- 邮箱邀请 / GitHub 导入（设计稿里的选项）：内部场景没有必要。
